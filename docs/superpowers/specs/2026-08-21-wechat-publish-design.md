# 微信公众号自动发布方案设计

## 一、背景与目标

本项目（DMLA，Deep Machine Learning Area）是一本以 VuePress 承载的机器学习应用设计技术书，共 94 篇中文章节（另有 91 篇英文），包含 283 张图片、81 个 mermaid 图、86 个表格，以及 runnable 交互代码块和 KaTeX 数学公式。

目标：将文档工程自动发布到微信公众号，形成一条**端到端零人工介入**的流水线——从 Markdown 源文件到公众号图文发布完成，中间不经过任何人工复制粘贴或第三方排版工具。

### 需求约束（已与用户确认）

| 维度 | 决策 |
|------|------|
| 目标账号 | 已认证的订阅号/服务号（企业主体认证） |
| 自动化边界 | 全自动：转换 → 图片上传 → 新建草稿 → 自动发布，零人工 |
| 发布策略 | 先挑 3-5 篇试点验证，通过后扩展 |
| 公式处理 | 全部渲染为透明底 PNG 图片 |
| 内部链接 | 降级为纯文本（锚点跳转、跨章节引用不可点击） |
| 运行载体 | GitHub Actions + Secrets 管理凭据（复用现有 CI 体系） |
| 发布语义 | `freepublish/submit`（发布到公众号但不推送通知，适合书稿连载） |

### 微信平台硬约束（须在管线中校验）

- 正文上限 **50000 字符**，图片最多 **500 张/篇**
- 标题最长 **64 字**，作者名 **8 字**，摘要不超 **120 字**
- 单张图片 ≤ **2MB**（超出需压缩）
- **2025 年 7 月起**：个人主体账号、企业主体未认证账号及不支持认证的账号将被回收发布类接口调用权限。**上线前置检查项**：确认目标账号为企业主体且已认证，否则流水线不可用。

## 二、架构总览

单条流水线，两个阶段。**阶段 1（转换）**可本地/CI 运行；**阶段 2（发布）**仅 CI 运行（需 Secrets）。

```
┌──────────────── 阶段 1：转换 ────────────────┐
│  docs/<章节>.md                               │
│     │ markdown-it 解析                        │
│     ├─ 公式 → KaTeX → puppeteer → 透明底 PNG  │
│     ├─ mermaid → mmdc → PNG                   │
│     ├─ runnable 代码 → 剥标记 → 静态代码块    │
│     ├─ 图片 → 尺寸/大小检查与压缩             │
│     ├─ 内部链接 → 纯文本；外链保留            │
│     ├─ 表格 → 微信兼容表格（内联样式）        │
│     └─ 输出：微信兼容 HTML + 待上传图片清单   │
└──────────────────────────────────────────────┘
                          │
┌──────────────── 阶段 2：发布（仅 CI）─────────┐
│  WECHAT_APPID / WECHAT_APPSECRET（Secrets）   │
│     │ 1. 获取 access_token（缓存）            │
│     ├─ 2. 逐张上传图片 → mmbiz CDN URL        │
│     ├─ 3. HTML 图片 URL 替换                  │
│     ├─ 4. 新建草稿 draft/add                  │
│     └─ 5. 提交发布 freepublish/submit         │
└──────────────────────────────────────────────┘
```

### 组件划分

每个组件单一职责、可独立测试，通过明确接口通信：

| 组件 | 职责 | 依赖 |
|------|------|------|
| `md2wechat` | Markdown → 微信兼容 HTML 转换器（纯函数，无网络依赖） | markdown-it（项目已有） |
| `formula2png` | KaTeX 公式 → 透明底 PNG | katex（0.16.47 已装）、puppeteer-core（25.3.0 已装）+ Chrome |
| `diagram2png` | mermaid 图 → PNG | mmdc（mermaid-cli 已装） |
| `wechat-api` | 微信 API 客户端（token 管理、素材上传、草稿、发布） | 官方开放接口 |
| `publish.js` | 编排入口（CLI） | 上述全部 |

## 三、转换器核心规则（md2wechat）

| 元素 | 处理规则 |
|------|---------|
| 标题 | `#`/`##`/`###` → `<h1/h2/h3>` 内联样式（16-19px、加粗、段距）；h1 映射微信"标题"字段，其余进正文 |
| 正文 | 段落 15px、1.75 行高、段距 8px，全部内联样式 |
| 行内公式 | `$...$` → KaTeX 渲染 → PNG（基线对齐 `vertical-align:middle`） |
| 块级公式 | `$$...$$` → KaTeX 渲染 → 居中 PNG |
| mermaid | ` ```mermaid ` → mmdc 渲染 PNG，居中 |
| runnable 代码 | ` ```python runnable ` → 保留代码、去掉 `runnable` 标记 → 微信代码块样式 |
| 普通代码 | ` ```python ` → 微信代码块样式（等宽字体、浅灰底） |
| 图片 | `![alt](assets/x.png)` → 上传后替换 CDN URL；超 750px 宽缩放；>2MB 压缩 |
| 内部链接 | `[文字](#锚点)`、`[文字](../../path.md#锚点)` → 仅保留文字（纯文本） |
| 外链 | `[文字](https://...)` → 保留为链接 |
| 表格 | markdown 表格 → `<table>` 内联样式（边框、单元格 padding） |
| 引用块 | `>` → 左侧竖线 + 灰底样式 |
| 列表 | 有序/无序列表 → 内联样式 |
| frontmatter | `---title: ...---` → 解析标题/摘要，不进正文 |

## 四、公式转图片实现（关键风险点）

- **渲染管线**：KaTeX `renderToString` → 套 `katex.min.css` → puppeteer 打开透明背景独立页面 → 按元素 `boundingBox` 精确截图，**仅截公式本身，背景透明 PNG**。
- **清晰度**：`deviceScaleFactor: 2`（2x 高清），避免微信压缩后模糊。
- **去重**：公式 → 内容 hash → 同 hash 只渲染/上传一次（书籍公式复用率高，显著减少工作量）。
- **行内/块级对齐**：行内公式 PNG 高度小（约 20-40px），用 `vertical-align: middle`；块级居中。
- **失败兜底**：KaTeX `throwOnError: true`，任何公式渲染失败 → 收集错误到报告，**该篇跳过发布**并输出诊断日志。绝不发布带坏公式的文章。

## 五、微信 API 客户端（wechat-api）

| 接口 | 用途 | 注意事项 |
|------|------|---------|
| `cgi-bin/token` | 获取 access_token | 每日 2000 次，必须缓存（CI 工作流内文件，7000s 有效期内复用） |
| `cgi-bin/media/uploadimg` | 上传正文图片 → 返回 `mmbiz.qpic.cn` URL | 不占素材库 10 万名额 |
| `cgi-bin/draft/add` | 新建草稿 | 标题≤64、摘要≤120、正文≤50000 字、图片≤500 张 |
| `cgi-bin/freepublish/submit` | 提交发布（不推送通知） | 异步任务，需轮询状态 |
| `cgi-bin/freepublish/get` | 查询发布任务状态 | — |
| `cgi-bin/freepublish/batchget` | 获取已发布列表（幂等检查） | — |
| `cgi-bin/freepublish/delete` | 删除已发布文章（不可逆） | 用于回滚 |

### 错误处理

- 429 限流 → 指数退避重试（最多 3 次）
- 素材上传失败 → 重试，超限报错
- `freepublish/submit` 异步任务 → 轮询直到 `success`/`fail`，`fail` 时拉取原因进报告
- **幂等性**：发布前用 `freepublish/batchget` 按标题匹配，已发布则跳过

## 七、失败与回滚

- **转换阶段失败**：CI 失败即止，不影响已发布内容（发布是最后一环）
- **草稿已建但发布失败**：草稿留在草稿箱，可人工后台删除或重发；记录 `draft/media_id` 便于追溯
- **发布半成功**：`freepublish/get` 查到 `fail` → 报告原因，CI 标记失败，人工介入（唯一可能需要人的地方）
- **回滚**：`freepublish/delete` 可删（不可逆，谨慎）；通常以"发修正版"替代

## 八、测试策略

- **单元测试**（jest）：转换器每条规则（公式/图片/链接/表格/代码块）独立断言
- **快照测试**：试点章节转换输出存为快照防回归
- **集成测试（dry-run）**：CI 完整转换 + 本地图片渲染，**不真正调用微信 API**（mock server 验证请求格式）
- **真实发布验证**：试点 4 篇真发，人工后台确认
- **Secrets**：`WECHAT_APPID`、`WECHAT_APPSECRET`（本地开发用 `.env`，不入库）

## 九、上线前置检查项

1. 目标公众号为企业主体且已认证（2025 年 7 月起个人/未认证账号被回收发布接口权限）
2. 获取 appid + appsecret，配置 GitHub Secrets
3. 服务器 IP 加入公众号后台 IP 白名单（GitHub Actions 出口 IP 为动态，需确认是否能加白名单，否则需用固定出口或备用方案）
4. 首次试点前手动在后台验证一次素材上传/草稿创建，确认凭据有效

## 十、遗留决策（后续确认）

- **IP 白名单问题**：GitHub Actions 出口 IP 不固定，若公众号要求固定 IP 白名单，需评估（a）用固定代理出口（b）改用本地定时任务触发（c）公众号后台确认是否支持豁免。**这是全自动路线的最大潜在阻塞点**，试点前必须验证。
- 英文章节（`docs/en/`）是否纳入发布范围，试点阶段暂不处理。
